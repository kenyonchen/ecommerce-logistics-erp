## 修复顺序建议

1. **S-01 + S-02 + M-01 + M-02 一起修**（同一认证链路）：让 `validateToken` 真正解析校验、filter 用注入实例、剥离 `Bearer ` 前缀、把角色写进 authorities 并输出到 `UserDetails`。这一组不修，其余授权设计都无意义。
2. **S-04 / L-06 / L-02**：凭据外部化（`${DB_PASSWORD}`、`${JWT_SECRET}`），引入 profile；轮换已入库的 `jwt.secret` 与默认口令。
3. **S-05 / M-05 / M-07**：`tenantId` 一律从令牌取；平台集成响应剔除 `apiSecret`（并加密存储）；列表接口加分页与权限过滤。
4. **S-03 / S-06**：修正路径规则为 `/api/platform-integrations/**`；在应用服务边界补 `@Transactional`（先覆盖下单、采购审批、库存移动三条主链路）。
5. **M-03 / M-04**：先做业务表 `tenant_id` 迁移，再启用 `TenantIsolationAspect` 的真实过滤逻辑（并补 `clearTenantId`）。
