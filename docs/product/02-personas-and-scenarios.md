## 2. 角色画像

### 2.1 跨境运营专员（张运营）

| 维度 | 内容 |
|---|---|
| 背景 | 26 岁，1~3 年经验，负责 3 个站点、2 个平台的日常运营 |
| 核心目标 | 让订单尽快发出去、不出错；平台上架及时、不断货 |
| 痛点 | 早上要在 3 个平台后台各导一次订单；同一订单可能在两个表里都出现；改价格/改库存要来回切后台 |
| 关键任务 | 平台订单归集 → 审核地址/异常订单 → 推送仓库发货 → 查看发货状态 → 处理异常件 |
| 成功标准 | 当天 14:00 前的订单当天出库；异常订单能在 1 小时内被识别 |
| 系统期望 | "我只要一个列表，能筛选平台、能批量推单，别让我再打开平台后台。" |

### 2.2 仓库主管（李仓管）

| 维度 | 内容 |
|---|---|
| 背景 | 32 岁，管一个 2000㎡ 自营仓＋一家海外仓，带 5 个拣货员 |
| 核心目标 | 库存数字和实物对得上；拣货效率高；盘点差异少 |
| 痛点 | 系统库存和实物不一致，拣货时才发现缺货；库位靠记忆；盘点用纸笔，录入要 2 天 |
| 关键任务 | 接订单拣货出单 → 打面单 → 交接物流 → 收货上架 → 周期盘点 → 处理缺货 |
| 成功标准 | 账实相符率 ≥ 99%；盘点能在半天内完成并生成差异表 |
| 系统期望 | "扫一下库位码就能知道放哪儿，库存动一下系统就要跟着动。" |

### 2.3 采购专员（王采购）

| 维度 | 内容 |
|---|---|
| 背景 | 29 岁，对接 10+ 供应商，负责爆款补货与新品首单 |
| 核心目标 | 不断货、不压太多库存、争取更优账期价格 |
| 痛点 | 缺货往往是客户投诉后才知道；采购单靠微信/邮件流转，审批进度不可见；到货后入库滞后，前端还在卖缺货 SKU |
| 关键任务 | 看库存/销量 → 建采购单 → 提交审批 → 跟催发货 → 到货确认 → 协同仓库入库 |
| 成功标准 | 采购需求响应 < 24h；缺货率 < 2% |
| 系统期望 | "谁能告诉我今天该补什么，以及我上周下的单到哪一步了。" |

### 2.4 财务专员（陈财务）

| 维度 | 内容 |
|---|---|
| 背景 | 35 岁，负责多店铺账务、汇率结算、平台回款核对 |
| 核心目标 | 清楚每个订单赚了多少，平台有没有少打款 |
| 痛点 | 平台回款扣了各种费用，和自己的账对不上；运费是月结的，很难摊到单；利润靠 Excel 拼 |
| 关键任务 | 归集订单收入 → 归集运费/采购/退款支出 → 与平台账单对账 → 出月度利润表 |
| 成功标准 | 月度结账 ≤ 3 天；单笔差异可追溯到具体单号 |
| 系统期望 | "收入、支出、退款要能按订单拉出来，告诉我差异在哪。" |

### 2.5 客服专员（赵客服）

| 维度 | 内容 |
|---|---|
| 背景 | 24 岁，同时应对 3 个平台的站内信 |
| 核心目标 | 快速回答"我的货到哪了"，把退换货处理掉 |
| 痛点 | 客户发信来查单，要切 4 个系统才知道状态；沟通记录没有留存，换人接手就断片 |
| 关键任务 | 按邮箱/订单号查客户 → 查看订单与物流轨迹 → 回复并留沟通记录 → 发起退货/重发 |
| 成功标准 | 首次响应 < 2h；同一客户的历史沟通可一次看全 |
| 系统期望 | "输入邮箱就能看到这个人买过什么、聊过什么、货在哪。" |

### 2.6 卖家负责人 / 老板（刘总）

| 维度 | 内容 |
|---|---|
| 背景 | 40 岁，公司决策人，不看操作只结果 |
| 核心目标 | 知道这周赚了多少、哪些品在赚钱、哪条物流渠道性价比高 |
| 痛点 | 数据要等人做表，看到时已过去一周；渠道选择靠采购/运营口头建议 |
| 关键任务 | 打开首页看板 → 看订单量/收入/异常 → 看品类毛利 → 拍板补货与渠道预算 |
| 成功标准 | 决策所需数据当天可见 |
| 系统期望 | "一个页面，不用问人。" |

### 2.7 平台运营管理员（Admin）

| 维度 | 内容 |
|---|---|
| 背景 | SaaS 提供方内部人员 |
| 核心目标 | 快速开户、控制租户状态、处理超期/欠费停用 |
| 关键任务 | 创建租户 → 建租户管理员 → 分配角色 → 停用/启用租户 → 配置系统参数 |
| 成功标准 | 开户 ≤ 5 分钟；误操作可回滚 |
| 系统期望 | "租户列表能搜能筛，停用后该租户立刻不能登录。" |

## 3. 核心场景（Scenario）

### S1｜张运营的一天：订单履约（最高频）

```
08:30  登录，看首页今日订单数、待发货数
08:35  进入订单列表，筛选"待处理"
08:40  挑出需要处理的：地址缺邮编、电话为空、同一买家重复下单
08:50  确认可发订单 → 推给仓库
09:00  仓库出面单 → 系统回写物流单号与轨迹状态
11:00  抽查几条"运输中"的订单，确认轨迹推进正常
16:00  处理异常：两条"配送失败"，联系买家重发或退款
17:30  复盘：今天发货 X 单，异常 Y 单
```

**当前系统支撑度**：🟡
- ✅ 能被定义：`/orders` 列表页、详情页、`/orders/create` 的存在形态正确
- ~~🟡 数据为 mock：列表与详情读的是页面内假数据~~ → ✅ **2026-01-25 已接真实接口**：`user-web/src/pages/order/OrderList.jsx`、`OrderDetail.jsx`、`CreateOrder.jsx` 均调 `orderApi`（列表参数在 `:41-60`），页面内已无 mock 数组
- ⚪ 缺失：批量推单、地址校验、异常标注、~~与平台订单拉取的衔接（同步是桩）~~ → **平台订单拉取已不是桩**（`PlatformIntegrationController:182` `/{id}/sync-orders` 经 `PlatformIntegrationApplicationService:99-102` 真调 `OrderImportApplicationService.syncFromPlatform(...)`，作业与逐行错误可在 `/api/orders/import/jobs`、`/jobs/{jobId}` 查），**但仍是手工触发**：全仓 0 个 `@Scheduled`/`@EnableScheduling` ⇒ "到达同步周期自动拉取"没有实现<br>❌ **2026-01-25 二次实测新增缺失项**：该场景里"下单→自动生成物流单"当前**不可演示**——`OrderCreatedEvent` 根本没被发布（ISS-062），实测 `POST /api/orders` 200 但日志零发布

### S2｜李仓管的盘点日

```
09:00  打印/导出选定仓库的库存清单
09:30  分区逐个清点，记录实盘数
12:00  回到系统录入实盘数量
12:30  系统生成差异：3 个 SKU 短少、1 个溢余
13:00  复盘差异原因 → 调整库存并生成调整记录
```

**当前系统支撑度**：🟡
- ✅ 存在 `POST /api/warehouses/{warehouseId}/inventory/count` 盘点接口
- ⚪ 缺失：差异表输出、盘点任务/快照 (frozen snapshot)、审批流、库存调整原因码、导出
- ~~❌ 不可用：库存移动/调拨接口直接抛 `UnsupportedOperationException`~~ → 🔄 **2026-03-22 复测：这条已不成立**。入库/出库/盘点/调整/调拨五种动作在 HTTP 层全部可用（`WarehouseController:151/:161/:171/:180`，`moveInventory:201-232` 四类分派、`transferInventory:237-252` 同事务双写；全仓 `UnsupportedOperationException` 0 处），`docs/qa/smoke-test-checklist.md` 4.5 已按「入 50→入 10→调 20→出 5→盘 45→调 10」实测全 200。
- 🟡 **换位后的三个新断点**：① **调拨没有前端入口**（`warehouseApi.moveInventory` 定义在 `api.js:297`，逐页 grep 0 调用 ⇒ 李仓管在页面上点不到）；② **没有变动流水表**（运行时库只有 `inventory_records`）⇒ 调整记录与差异都只能靠日志回溯；③ **入库/出库不带库位**（`WarehouseApplicationService:118` 恒 `locationId = null`），所以这条时间线里「12:30 生成差异」之后的按库位复核无法支撑

### S3｜王采购的补货决策

```
09:20  打开库存看板，找"缺货/不足"状态的 SKU
09:40  挑出 12 个需补货 SKU → 汇总成一张采购单
09:50  提交 → 老板审批通过
10:00  发给供应商，标记运输中
+3 天  供应商到货 → 标记已送达 → 仓库收货上架
```

**当前系统支撑度**：🟡
- ✅ 采购审批状态机完整（`pending → approved/rejected → in_transit → delivered → cancelled`），API 齐全
- ~~⚪ 缺失：到货后**自动入库**（采购与仓储无联动）、缺货自动生成采购建议、供应商主数据、审批人/意见字段~~ → 🔄 **2026-03-22 复测：四项里前两项一项已交付、一项半交付，只剩「供应商主数据」为纯缺位**。①**到货自动入库 = 已交付**（`PUT /api/purchases/{id}/delivered` 同事务逐行加库存 + 记采购应付，`PurchaseApplicationService.java:256-262`）；②**审批人/意见/时间 = 已交付**（`approved_by`/`approved_at`/`approval_comment` 三层齐备，拒绝强制填原因）；③**缺货自动生成采购建议 = 半交付**——消费端已建齐（`EventHandler:92-105` + `InventoryShortageEventConsumer`），但 `InventoryShortageEvent` 在出库路径上从未进入发布器（`WarehouseApplicationService.inventoryOut` 不调 `publishDomainEvents`）⇒ 事实上不会触发，且触发的是**无明细的空采购单**、租户硬编码 `default-tenant`；④**供应商主数据 = 仍缺**（运行时库 42 张表无 `suppliers`，只有 `supplier_id`/`supplier_name` 快照）
- ~~⚪ 前端 `PurchaseList` 仍是 mock~~ → ✅ **2026-01-25 已去 mock**（ISS-015/016 收尾）：`PurchaseList.jsx:5,78` 走 `purchaseApi.getPurchaseOrders(status)`，`PurchaseDetail.jsx` 7 个调用点（含 approve/reject/in-transit/delivered/cancel 与加采购项），`CreatePurchase.jsx:68` 真建单。~~⚠️ 本场景里"到货后自动入库"仍**不成立**：`purchase-events` 无任何消费者，且 `PurchaseApplicationService` 根本没有入库动作（见 [05 附录](./05-core-business-flows.md)）~~ → 🔄 **2026-03-22 复测：本场景的这一步已成立**。到货入库不靠事件订阅、所以「`purchase-events` 无消费者」不再阻断它——`PurchaseApplicationService.markPurchaseOrderAsDelivered()`（`:256-262`）在同一事务里同步完成入库与应付（`:281-293`、`:299-310`），前端「确认送达」还带二次确认（`user-web/src/constants/purchase.js:48-53`）。本场景**现在仍断的**只剩「缺货→自动生成采购建议」那一环（消费者已建齐、上游 `InventoryShortageEvent` 发不出来，见 [../spec/purchase.md BR-12](../spec/purchase.md)）

### S4｜陈财务的月度对账

```
每月 1 号  导出上月订单收入流水
          拉取平台账单 CSV
          逐笔比对：金额、退款、平台佣金
          标记差异 → 生成调整流水
          出利润表给老板
```

**当前系统支撑度**：⚪
- ✅ 财务流水 CRUD + 按状态/类型/关联单据查询（`/api/finance/transactions/**`）
- ⚪ 缺失：自动由订单/物流/采购生成流水、对账差异处理、报表导出
- 结论：**对账场景目前无法用系统完成**，`/finance` 页面只能演示手工录入一条流水
